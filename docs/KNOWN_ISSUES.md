# Known issues

1. **Test evaluation ran twice.** `finanomaly evaluate` was executed once and crashed in the seed stability section (a loop variable bug introduced by an automated rename) after the first part had already written the test summary. It was fixed and rerun; the model, threshold and test code for the first part were unchanged, so the outputs are identical. No decision depended on the first run, and the first run's printed numbers were not read before the rerun.
2. **Very few events.** Three validation events and six test events: recall takes coarse values and ties dominate model selection. Per-event tables matter more than aggregates.
3. **Champion threshold drift.** The isolation forest threshold, set for 3 false alarm episodes per year on 2015 to 2018, produced more false alarm episodes per year on the test period (see `docs/PROMOTION_DECISION.md`).
4. **Alarm episode metric can hide long alarms.** An alarm run that overlaps an event window is not counted as a false alarm episode. The LightGBM entry has few episodes but a larger share of alarm days than the other models (see `results/alarm_share.json`), and in the feature ablation a model with only rates and FX features alarmed on every test day while showing zero false alarm episodes. Calibration caps alarm days, but the test evaluation reports the share rather than enforcing it.
5. **Thresholds drift.** The isolation forest and autoencoder exceeded the 3 per year budget in the test period.
6. **Autoencoder walk-forward** detected fewer events than the fixed schedule (see the README table); the annual threshold recalibration on the previous four years is a plausible cause (only a few events in each window) but this was not investigated further.
7. **MLflow server memory**: version 3.17.1 uses about 1.6 GiB at start-up, so the compose service needs a 2 GiB limit; on a Docker VM of 2 GiB or less it is killed.
8. **Not run**: the GitHub Actions workflow, the full compose trainer set (only Isolation Forest completed, see `results/deploy_log.md`), Linux and macOS.
9. **Event evidence is thin for three events** (flash crash 2010, ECB hike 2022 and August 2024 had small daily DAX moves); they are kept because the specification names them, and are marked in `data/events.yaml`.
10. **Review of alarms**: several of the 20 reviewed episodes have no dated source for what happened, or only context; the count is at the end of `docs/FALSE_ALARM_REVIEW.md`.
11. **Raw cache briefly committed, history rewritten.** A duplicate copy of the first raw cache (`data/raw_start2000/`) was committed by mistake; it was removed from every commit with `git filter-branch` (the repository had no remote). The duplicate was also deleted from the working tree by the rewrite; the same files remain in `data/raw/` (the first-fetch caches without the `_from1999` suffix), so no data was lost. The rewrite changed all commit hashes: the `git_commit` values stored in `results/registration.json` consumers, MLflow tags, the export manifest and `.build/progress.json` refer to earlier hashes of the same content.
